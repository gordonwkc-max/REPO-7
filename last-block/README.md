# The Last Block

A twelve-second voxel short. A tiny builder drops the one missing plank into a hole in a night
bridge, and a lantern cart rolls across on it.

## What it is about

The point of the film is *the mechanism*, not the mood. It is staged so the reason the crossing works
is visible on screen, in three physical beats:

1. **The hole.** The cart's wheels carry it up the bridge and stop dead at a rectangular slot cut
   clean through the deck — one deck plank is missing, and there is nothing under it but the ravine.
   Nothing crosses that.
2. **The fit.** The builder runs in, lays his plank on the deck lip, shoves it across the slot and
   drops it in flush. The deck surface becomes continuous again — the block is exactly the missing
   piece, and when it lands the seam flashes and dust puffs out of the joint.
3. **The load.** The cart rolls on. As each wheel passes over the block, the span lights up along its
   whole length and both of its ends glow where they sit on the deck — the weight is travelling
   *through* the block into the two banks. No block, no path for the weight, no crossing.

## How it was made

Every frame is drawn by a ~350-line software renderer written for this piece: a pinhole camera
projects boxes and quads which are flat-shaded, painter-sorted and fogged onto a `@napi-rs/canvas`
bitmap; the 360 PNGs are piped to a static ffmpeg build, and the soundtrack is synthesised from noise
and sine partials in `src/audio.mjs`.

No 3D package, no engine, no stock assets — three small ES modules and the platform canvas.

## Rebuilding it

Requires Node 20+.

```bash
cd last-block
npm init -y >/dev/null
npm install @napi-rs/canvas @ffmpeg-installer/ffmpeg
./render.sh                     # 360 frames -> encode -> soundtrack -> mux
```

`render.sh` writes `last-block.mp4` in this folder. A full build takes about two minutes.

Rendering a single moment while you iterate (much faster than a full build):

```bash
node src/render.mjs --still 4.86 build/seat.png     # one frame
node src/render.mjs --sheet 0 2.5 4.8 6.2 9 11.8    # a handful into build/
node src/audio.mjs build/audio.wav                  # the soundtrack alone
```

## Editing it

Everything is a pure function of time — there is no simulation state and no randomness that is not
seeded, so any frame can be rendered on its own and two runs are identical.

| File | Holds |
|---|---|
| `src/scene.mjs` | the world, the builder's pose rig, the cart, the plank, the light, the titles |
| `src/engine.mjs` | projection, shading, depth sort, fog, glows, the sky — no story in here |
| `src/render.mjs` | canvas setup, frame loop, `--still` / `--sheet` / `--frames` |
| `src/audio.mjs` | the soundtrack, driven by the same timeline |

Useful handles:

* `BEAT` in `scene.mjs` — the beat sheet: when he runs, kneels, seats the plank, taps it, when the
  cart starts again.
* `SEG` in `scene.mjs` — the four camera setups (wide / builder close / wheels / crane out), each a
  start and end camera that get eased between.
* `cartX(t)` — the cart's position, deliberately not linear: it brakes to a stop at the hole and
  pulls away again once the block is in.
* `loadState(t)` — which wheels are currently over the block; it drives the load-path glow.
* `PAL` in `engine.mjs` — the whole palette.

Development hooks (env vars, harmless if unset): `LB_CAM="az,el,dist,tx,ty,tz"` pins the camera,
`LB_ONLY=builder` draws the rig alone, `LB_DBG=1` prints the pose, `LB_FONT=/path/to.ttf` swaps the
title font.
